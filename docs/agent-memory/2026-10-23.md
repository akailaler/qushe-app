### ③ 踩坑：tag 打在了上一个提交上
顺序错了：改版本号 → 构建 → `release.py`（打 tag 并推送）→ **最后才 commit**。
于是 `v1.3.91` 指向上一提交，`git show v1.3.91:app/build.gradle.kts` 里是 1.3.90。
**网页上完全看不出来**，只有翻 tag 才发现。
- 修：`git tag -f -a v1.3.91 <正确提交>` + `git push --force origin v1.3.91`

  `versionName` 与工程不一致，直接退出。
**正确顺序：改版本号 → 构建 → commit → `python release.py`。**

## 1.3.92（三键导航白边 + 关备份 + README 截图位）

### ① 红米 K20 Pro 底部白边：`enableEdgeToEdge()` 的默认底色
不带参数的 `enableEdgeToEdge()` 用 `SystemBarStyle.auto(lightScrim, darkScrim)`，
会**跟随系统是浅色还是深色**挑底色：系统浅色时导航栏给 `白色 0xe6` 半透明底。
手势导航 / 系统深色的机器上这层被内容盖住看不出来；
**三键导航 + 系统浅色**（MIUI 12.5）时 Android 10 不允许导航栏真透明 ⇒ 露成白边。
- 修：`enableEdgeToEdge(statusBarStyle = SystemBarStyle.dark(Color.TRANSPARENT), navigationBarStyle = ...)`，
  再 `window.isNavigationBarContrastEnforced = false` / `isStatusBarContrastEnforced = false`（API 29+）。
  **第二个来源**是系统的"对比度蒙层"，只管颜色是治不好的。

### ② 关掉云备份
`android:allowBackup="false"` + 新建 `res/xml/data_extraction_rules.xml`
（cloud-backup 与 device-transfer 都排除 sharedpref/file/database/root）。
**allowBackup 只管云备份，Android 12+ 的换机直传不受它控制**，必须靠 rules。
代价：重装/换机后记录清零（现在也没有导入导出功能了）。

### ③ README 截图位
`docs/screenshots/01-home.png` … `04-folders.png`（540×1170 占位图，
用 venv 里的 **Pillow** + `C:/Windows/Fonts/msyh.ttc` 生成；
系统自带的绘图 API 走 shell 被安全策略拦了）。
README 顶部用 `<p align="center">` 四张 23% 宽并排 + 一行说明；
`docs/screenshots/README.md` 写了替换规则和"别露私人照片"。

### ④ release.py 的 tag 校验（连着两次踩坑）
1. 第一次：先发版后提交 ⇒ tag 打在上一提交（已修，加了 `assert_releasable`）。
2. 第二次：推送时 **DNS 挂了**，但 `ensure_tag` 只打了一句警告就继续，
   GitHub 建 Release 时**按默认分支自动补了一条 tag** ⇒ 下载页 v1.3.92、源码是上一版。
   - 现在：`ensure_tag(tag, ver)` 先看**tag 指向的提交里 `versionName` 是否等于目标版本**
     （不是"是不是 HEAD"——发版后还会继续提交），
     再看 **远端 refs 的真实指向**（`ls-remote refs/tags/x^{}`，走镜像可读）。
     推送走直连、读 refs 走镜像，两者可达性不同 ⇒ **不能拿 push 的返回值当结论**。
   - 修远端的办法：`git tag -f -a vX -m '取舍 vX'` + `git push --force origin vX`，
     Release 和附件不受影响。

### ⑤ 事故：token 回显
用镜像推送时把带 token 的 URL 拼进了命令行，**日志里直接把 `gho_...` 打了出来**
（只用 `replace` 处理了 stdout/stderr，没处理我自己的那行 `print`）。
以后打印命令必须先脱敏；必要时让用户重登 GitHub Desktop 让旧 token 失效。

## 1.3.93（外观深浅色 + 一堆收尾）

### ① 深浅色：**颜色常量改成"调色板 getter"**，350 处调用点一行没动
`Theme.kt` 原来是一堆顶层 `val Ink = Color(...)`。难点是**相当一部分引用在
`Canvas` / `drawBehind` / `graphicsLayer` 这类非 Composable lambda 里** ⇒
不能改成 `@Composable get()`。
做法：
```kotlin
data class QushePalette(...)               // 13 个色
private val DarkPalette / LightPalette
object QusheColors { var palette by mutableStateOf(DarkPalette) }
val Ink: Color get() = QusheColors.palette.ink      // 名字不变
```
`QusheTheme(mode)` 里在组合期把 palette 换掉（子节点同帧读到新色），
并用 `WindowCompat.getInsetsController` 改系统栏图标明暗。
**默认 THEME_DARK**（保持原样），浅色是选项。
浅色强调色要压暗：深色下的马卡龙色（#35D0A5）放白底上看不清。

### ④ 瀑布流左右滑的"轻微闪烁"：两个来源
1. **系统缩略图是正方形**：`loadThumbnail(Size(side, side))` 先居中裁成方块，
   再被我们 Crop 进 4:3 格子 —— 那是在**已裁过的方块**上再裁一刀，
   取景和主图直接 Crop 不一样 ⇒ 切到高清时画面"挪一下"。
   改成 `targetSize()` 按请求比例要（`loadThumbnail(uri, Size(w,h))`）。
2. **placeholder 是"换图"动作**：Coil 就绪时先卸 placeholder 再挂新 painter，
   中间可能有一帧空。改成**两层**：底层 `Image(placeholder)` 常驻，
   上层 `AsyncImage` 硬切覆盖。
`rememberSystemThumbnailPlaceholder(uri, wPx, hPx)` 现在必须传尺寸，
调用点改成传 `systemPlaceholder: Boolean`（尺寸在 DayCell 里算）。

## 1.3.94（浅色模式补齐"浮层"）

### ① 症状：浅色下这几个地方还是深色
整理页的按钮和胶囊、收藏预览的背景、瀑布流四角的按钮。
**根因**：这些是"浮在内容上的控件"，用的是**硬编码的黑蒙层**
（`0x66000000` / `0xB3000000` / `0x26FFFFFF` 描边 / `Color.Black`），
不是 `Ink` —— 所以 1.3.93 只换「页面底色」时它们没跟着翻。

### ② 修法：调色板加 5 个"浮层 token"
| token | 深色 | 浅色 | 用在哪 |
|---|---|---|---|
| OverlaySoft | 黑 40% | 白 40% | 圆钮底（RoundActionButton / DayCircleButton） |
| OverlayStrong | 黑 70% | 白 70% | 信息胶囊 |
| OverlayFade | 黑 60% | 白 60% | 顶栏渐变 |
| OverlaySolid | 黑 95% | 白 95% | 底栏渐变收口 |
| OverlayBorder | 白 15% | 黑 15% | 浮层描边 |
前景色不用另设：里面的图标/文字本来就用 `TextPrimary`，会自己翻。
另外两处 `Color.Black` 背景（收藏预览、瀑布流放大）改成 `Ink`。

**保留不翻的**：贴在**照片上**的角标（视频时长 / 长图 / 截屏 / 回收站天数）
—— 那些底图颜色不可控，深色角标 + 白字在任何照片上都读得出来。视频控件同理。

**教训：做主题化时，除了"页面底色"，还有一类颜色叫"浮层"**——
它们往往是以 `0x??000000` 的形式散落在各处的，grep 半透明色比看图快。
