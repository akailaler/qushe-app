## 1.4.6（音频焦点 / 拆文件 / 单测 / 使用说明）

### ★★★ Gradle + 中文路径 + @argfile：单测全部 ClassNotFoundException
症状：测试类编译出来了、classpath 里也确实有 `build/tmp/kotlin-classes/debugUnitTest`，
但 JUnit 报 `ClassNotFoundException: com.qushe.app.core.FormattersTest`。
根因：Gradle 把测试进程 classpath 写进 `@gradle-worker-classpath*.txt`，
**用的是守护进程的 file.encoding**（`gradle.properties` 里写的 UTF-8），
而 **JDK 17 读 @argfile 用系统默认编码（中文 Windows = GBK）** ⇒ `小工具` 变乱码 ⇒
整个 classpath 失效（JUnit 自己在 ~/.gradle 下的 ASCII 路径里，所以能起来）。
修法：`org.gradle.jvmargs` 里**去掉 `-Dfile.encoding=UTF-8`**（源码读写不受影响：
Kotlin 固定 UTF-8 读源码，javac 由 AGP 传 UTF-8，已显式写 `compileOptions.encoding`）。
诊断方法：`gradle testDebugUnitTest --info` 看 `Starting process 'Gradle Test Executor'` 那行有没有 `@...txt`。

### ③ DayViewScreen.kt 3569 行 → 6 个文件
`DayViewScreen`(728) / `DayFilmstrip`(1446) / `DayCell`(623) / `DayChrome`(386) /
`DayZoomOverlay`(516) / `DayInfoSheet`(77)。全部同包，`private` 统一放宽成 `internal`。
**拆分方法（可复用）**：
- 用**「下一个顶层声明的起点 - 1」**划块，**不要用括号配对** ——
  字符串模板/raw string 会让配对提前结束（第一版把 DayCell 截断了 100 行，靠编译才发现）。
- 声明起点要向上吃掉 `@注解` 与 KDoc（遇到空行停）。
- import 用"简单名在正文里出现过"筛；**`getValue`/`setValue` 必须强留**
  （`by remember` 的操作符不在正文出现，剪了会报 "Property delegate must have…"）。
- 验证：把原文与拆分后的文件都去掉 import/空行、`private→internal` 归一后做
  `Counter` 逐行比对 —— 这次 3274 行，差异只有我自己的 44→48 / 52→56。
- 顺手删掉死代码 `dayKindLabel`（全工程零调用）。

## 1.4.7（下滑退出补回来 / 去掉隐藏长按 / 使用说明重写）

### ① 收藏页的"长按直接取消收藏"删掉
用户完全不记得有这个功能 —— 这就是问题本身：**界面上没有任何提示，
而它又会改数据**。指头压久一点就悄悄改掉一条。
现在缩略图只剩单击（打开预览），要取消收藏就进预览点星形/红心。
**教训：会改数据的动作不要挂在没有提示的隐藏手势上。**

### ② 整理照片页补回"下滑退出"
来源：早年"下滑"是收藏，1.3.x 把收藏挪到左下角按钮后，下滑就空着没人接
（代码里还留着注释"下滑不再触发任何动作"）。现在接上"退出这一组"。
实现要点：
- `SwipeDecision` 加 `DISMISS`；判定 `y >= max(0.22*屏高, vLimitPx)` 或
  `v.y >= 1200px/s`（和 `MediaPreviewOverlay` / `DayZoomView` 同一档手感）。
- 位移只走 **0.45 屏 + 整页 200ms 淡出**（`graphicsLayer { alpha }` 挂在
  `BoxWithConstraints` 上）；**不能飞整屏** —— 飞太远会先把下面那张露出来，
  观感像"换了一张"。
- 收尾走 `finish()`（不是直接 onConclude）：已标记项要照常交出去；
  也**不调 onSeen** —— 退出不是"看过这一张"。
- 顶部提示文案改成「上滑删除 · 下滑退出」。

### ③ 使用说明重写
- 改掉有歧义的那句：「留着的**滑走**就行」（原文"往下划走"会和"下滑"冲突）。
- 删掉长按删除的描述，补上下滑退出；并明确 **视频页上下滑是"切下一个"，不是退出**。
- 新增"和别的清理工具不一样的地方"对照表（不联网 / 只要读权限 / 没有进度条 / 删进回收站）。

## 1.4.8（下滑退出露底牌 / 使用说明瘦身）

### ① 下滑退出时看到下一张
底下那张"下一张"的淡入原来写的是 `abs(dy)` —— 往上、往下都在增加，
所以下滑退出过程中底牌先浮出来了。改成 `(-dy).coerceAtLeast(0f)`：
**只有向上位移才算"正在删除"**，下滑退出时背后是空的（Ink）。
**规律：一个量在两个方向的手势里共用时，先问"另一个方向该不该有同样的效果"。**

### ③ 回收站到底是哪一层（事实核对）
用户说"进的是取舍自己的回收站"，代码不是这样：
- 删除：`MediaStore.createTrashRequest(resolver, uris, true)`（MediaRepository.kt:761）
- 回收站页：`QUERY_ARG_MATCH_TRASHED = MATCH_ONLY` 查 images/video 两张表（MediaRepository.kt:723）
- 恢复：`createTrashRequest(..., false)`（:766）
即：**App 没有自己的回收站目录**，那个页面是系统 MediaStore 回收站的视图
（剩余天数是用自己记的删除时刻倒推的）。
文档里索性不写"谁的回收站"，只说"删除后进「回收站」，30 天内可恢复" ——
对用户来说这就是取舍里的那一页，而且两种说法都指向同一批数据。
