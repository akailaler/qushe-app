# 2026-10-20

## 1.3.85（胶囊回到按钮行 + 瀑布流尽头的原地抖动 + 橡皮筋）

### ① 胶囊：从"独立一行"改回"与按钮同一行"
用户要求放回去，并明确指出**收藏页允许略偏右、不必严格居中**。
- 根因回顾：`InfoPill` 把 `contentMaxWidth = 230.dp` 写死，**只约束文字区**，
  加上图标与左右内边距，整个胶囊 280dp —— 比两颗按钮之间剩下的空间还宽，
  于是压住星形内侧，点收藏先命中胶囊的 `clickable`（1.3.84 的诊断是对的）。
- 正解不是"挪走"，而是**让胶囊自己不知道宽度**：
  `contentMaxWidth: Dp? = null`，宽度完全由父容器约束。
  - 整理页 / 瀑布流大图：`Box{ 按钮 align Start/End; InfoPill.align(Center).padding(horizontal = 52.dp) }`
    —— padding 收缩的是**约束**，所以胶囊最大宽 = 屏宽 − 两侧按钮 − 间隙，
    结构上不可能重叠，且仍然真居中。
  - 收藏页：`Row{ 心 星 Box(weight(1f)){ 胶囊 } 删除 }` ——
    胶囊在**剩余空间**居中，天然偏右，正合用户"不必严格居中"的要求。
- **教训：组件里所有 `widthIn(max = 固定值)` 都是"它不知道旁边有什么"的定时炸弹。**
  宽度上限应该由父容器给，而不是猜。

### ② 滑到尽头还在原地滑 / 像闪烁 —— 两排 maxValue 不相等
下排 `offsetHalfRow` 会在 Row 里插一个 `rowOffsetPx` 的 Spacer（半格，约 100~200px），
但 `ownSpan`（上报的内容总宽）**没算它** ⇒
- 上排内容宽 = span，下排 = span + rowOffset；
- 两排各自的 `horizontalScroll` 算出的 maxValue 差半格；
- 共用一个 `ScrollState` ⇒ 到尽头后一边夹一边放，手指继续划就来回抖。
**修法：`ownSpan` 加 `rowOffsetPx`。** 两排 maxValue 恒等，尽头就是尽头。
**教训：凡是"为了排版插入的 Spacer"，都要问一句它算不算内容宽度。**
（本项目里内容宽 / 两排对齐 / 刻度条分母是同一个数，漏一处三处全歪。）

### ③ 尽头橡皮筋（iOS 手感）
- `OverDrag`（@Stable，两排共用一份）：`raw`（手指累计）+ `draw`（阻尼后绘制值）。
- 阻尼：`limit * raw / (limit + |raw|)`，limit = 96.dp。渐进变硬，不突变。
- 位移画在 `graphicsLayer { translationX = -draw }`，且必须放在
  **`horizontalScroll` 之前**（之后会被滚动容器自己 clip 掉，看不见）。
- 拖拽循环里用 `dispatchRawDelta` 的**返回值**算 leftover：
  `consumed = scroll.dispatchRawDelta(delta); leftover = delta - consumed`。
  只有"已经在头/尾 + `abs(leftover) >= 1f`"才算拉出。
  1px 死区是必须的：`ScrollState` 内部 `roundToInt`，正常滚动每帧都差零点几像素。
- 反向拖：先收皮筋，收完的余量再滚内容（否则反向第一段手感像卡住）。
- 松手：`animate(raw → 0, spring(MediumBouncy))`，绘制值继续走阻尼 ⇒ 带回弹余震。
- 惯性 `while` 里到边界就 `break`，不再空转（原来空转也是"原地滑"观感来源）。

### ④ 待办（用户只是问，未改）
瀑布流拖滑块时的空白格 —— 建议用已有的 `SystemThumbnailFetcher`
（系统缩略图 1~2ms）做**垫底层**，高清图到达后盖上。代价：每格多一次
MediaStore 查询 + 约 1MB 内存，视觉上有"先糊后清"。等用户决定。

## 1.3.86（尽头留白 + 系统缩略图垫底 + 设置页行高）

### ① 滑到尽头还剩半屏空白
不是橡皮筋没做对，是**两端各垫了半个视口**（为了让首尾能居中）。
`edgePad` 从 `maxWidth/2` 降到 **8dp**，所有用到它的地方（ownSpan / focusTarget /
ownMaxScroll / shift / 两端的 Spacer）一次替换即一致。
代价（已接受）：最前 / 最后那几张贴边停，不再居中。
顺手修了 `onCenterDay` 的 `centerPx`：原来只减了 rowOffset，没减垫片 ——
垫片是半屏时标题日期偏半屏，现在只剩 8dp。
**注意**：`splitRowsBalanced` 的两排长度差最多一格，右端仍可能露出
"差值宽"的空白（用户若继续报，就去做分排的局部优化，不能靠 padding）。

### ② 方案一：每格先用系统缩略图垫底
`SystemThumbnailFetcher`（`loadThumbnail`，1~2ms，最长边 512）早在库里，
而且 `rememberFocusPlaceholder` 已经是"异步 painter 当 placeholder"的现成写法。
把调用条件从 `isFocusCell && !isLongImage` 放宽到 `!isLongImage` 即可。
- **长图必须排除**：system fetcher 对长图会返回 null（min-side 检查），
  请求随后落到默认解码器 ⇒ 为 828×30656 解 101MB。
- `fadeIn = placeholder != null` 顺势让所有格子的主请求开了 crossfade ⇒
  "糊 → 清"是渐变的。代价是每格加载完多一个 200ms 动画器，要真机看拖动是否掉帧。

### ③ 设置页"上面几行间距大"
不是 padding，是**行高**：Material3 `Switch` 带 `minimumInteractiveComponentSize`
占 48dp，而胶囊（`Chip`）是 8+8+20 = 36dp。
在 `SettingBlock` 里给 `trailing()` 套 `Box(height = 36.dp)`，一处解决全部块。
代价：开关触摸目标 48 → 36dp。
