# 2026-10-23

## 1.3.91（文件夹网格可选 2/3 列 + Release 附 SHA-256）

### ① 文件夹网格列数
- 新增 `Prefs.folderColumns`（默认 **3**，`coerceIn(2, 3)`），
  `FOLDER_COLUMNS_CHOICES = listOf(2, 3)`，`KEY_FOLDER_COLUMNS = "folder_columns"`。
- **state 必须由 `AppRoot` 持有**再往下传（`prefs.folderColumns` 是 SharedPreferences 读，
  设置页改完不会触发重组）—— 和 `relativeDates` 同一个坑。
- `HomeScreen` 接 `folderColumns`，转给 `FolderSheet(columns=)`；
  `GridCells.Fixed(columns)`；三列时间距 12→10dp、标题 `bodyMedium`→`bodySmall`
  （3 列在 360dp 屏上每格约 100dp）。
- 设置页在「每组数量」下面加了「文件夹网格」，两颗胶囊 `2 列 / 3 列`。

### ② Release 附 SHA-256
- `release.py` 用 `hashlib.sha256(apk.read_bytes())` 算（对**要上传的那个文件**算，
  不读构建日志），写进说明的 `### 校验（可选）` 代码块。
- 已有的 v1.3.89 / v1.3.90 用 **GitHub API 附件的 `digest` 字段**补上（`sha256:...`），
  比自己重算可信。

### ③ 踩坑：tag 打在了上一个提交上
顺序错了：改版本号 → 构建 → `release.py`（打 tag 并推送）→ **最后才 commit**。
于是 `v1.3.91` 指向上一提交，`git show v1.3.91:app/build.gradle.kts` 里是 1.3.90。
**网页上完全看不出来**，只有翻 tag 才发现。
- 修：`git tag -f -a v1.3.91 <正确提交>` + `git push --force origin v1.3.91`
  （Release 和附件不受影响，已验证）。
- 防：`release.py` 新增 `assert_releasable(ver)` —— 工作区不干净、或 HEAD 里的
  `versionName` 与工程不一致，直接退出。
**正确顺序：改版本号 → 构建 → commit → `python release.py`。**

### ④ 解释过但没改的两项（用户只想先理解）
- `BuildConfig.VERSION_NAME`：现在设置页那行版本号是**手写死的第二个真源**，
  靠 `verify.py` 的"四处一致"事后兜。改法是开启 `buildFeatures { buildConfig = true }`。
- `allowBackup="true"`：备份的是**本应用的私有数据**（收藏/喜欢/统计/设置），
  不是小米相册里的照片；国内 ROM 走厂商云。关掉则重装后记录全丢。
