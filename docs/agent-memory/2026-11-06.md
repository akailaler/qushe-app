# 2026-11-06

## 2.2.0 瀑布流空白三处修复 + 「初始测试」配色回归

用户报「连续清理图片之后，偶发瀑布流加载慢导致部分卡片空白」。

### ★ 根因：删除改变了列表下标，而格子是按**下标**做 key 的
`DayFilmstrip` 里 `key(global)` 用的是照片在 `items` 里的索引。
删掉一张，后面所有照片的下标整体前移一位 ⇒ **key 全变** ⇒
Compose 认为整排都换了新内容，把每个格子的组合销毁重建，
连同 `imageRequest` 的 remember 一起重来 ⇒ 整屏缩略图重新排进解码队列。
连续清理几十张 = 连续重建几十轮，表现就是"删完回来卡着白一下"。
**改成 `key(item.storeKey())`**：身份跟着照片走，删一张只销毁那一格。

### 另外两处（都为了"不出现空洞"）
1. 每格加 `background(Surface2)` 兜底 —— 占位和主图都没就绪时，
   原来透出的是页面底色，一屏破几个洞；现在是一张安静的深色卡片。
   长图格子尤其需要（它拿不到系统缩略图，只能等区域解码）。
2. 垫底图改走**独立 ImageLoader**（`ThumbnailPlaceholderLoader`）：
   原来占位和主图共用一个 loader 的解码通道，主图一张几十 ms、
   一屏十几张排队，把本该 1~2ms 就到的系统缩略图压在后面。
   独立 loader = 独立 dispatcher(4) + 48MB 内存缓存 + 自己的磁盘目录
   （**必须换目录**：Coil 的磁盘缓存对同一目录独占，两个 loader 会打架）。

### Coil 2.7 没有 Priority
想给占位请求提优先级，`ImageRequest.Builder` 里根本没有 `priority` ——
那是 Coil 3 才有的 API。`coil.request.Priority` 类在 2.7 的 aar 里也不存在。
**判断 API 存不存在要 javap 反编译看**，别凭记忆写。
