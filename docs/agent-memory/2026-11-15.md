## 2.3.0 沉浸态藏系统栏 / 点赞动画串页 / 瀑布流预取

### 1. 沉浸态要藏的是**系统栏**，不是我们自己的控件
用户："沉浸模式能不能隐藏系统状态栏（包括看图和看视频）"。
此前"沉浸"只是把顶栏底栏淡出，系统状态栏还占着一截。
新增 `ui/common/SystemBars.kt` 的 `ImmersiveSystemBars(owner, hidden)`，
挂三处：整理照片页第三态（chromeHidden）、瀑布流放大（!chromeVisible）、视频横屏全屏（fullscreen）。

**★ 必须用 owner 集合，不能用一个 Boolean**：这三处会叠着
（整理页沉浸着捏合进"回到那天"、放大页又要求沉浸），各自直接 hide/show
会导致"退一层，状态栏莫名其妙冒出来"。记的是"现在有几个人要求隐藏"，
集合空了才真 show。`BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE` 留着轻扫唤出。
- 同包的 `VideoSurface.kt` 早就有一个 public `Context.findActivity()` ——
  自己又写一份会 `Conflicting overloads`，直接复用。

### 2. 点赞动画跟着滑到下一张（真 bug，两个原因都占了）
`DoubleTapFlash` 是**页面级**状态，动画跑 1.2 秒，翻页时没人清它 ⇒ 画到下一张脸上。
修法不是"翻页时清空"（时机难挑，滑得快根本轮不到），而是
**给 flash 带上 targetKey（照片的 storeKey），渲染时只认当前这张**，
再补一条 `LaunchedEffect(index){ flash = null }` 收尾。三处全改（照片/放大/视频）。

### 3. 瀑布流往后滑追不上 —— 原因和解法
**解码发生在"进入视野之后"**。格子本身早就组合好了（区间前后各伸 0.5 屏），
但图片请求是组合那一刻才发的。滑动 8000px/s 时 0.5 屏 ≈160ms，只够解 3-4 张，
一屏进 5-6 张，后面那两张就赶不上 ⇒ 露出底色。
"看的图片有点多之后才明显"是第二层：Coil 内存缓存默认 25% 堆上限 ≈ 50 张
（0.6 倍解码每张约 2MB），一天的图几百张，滑过 50 张开始 LRU 淘汰 + GC 压力。
- 解法：`PreloadAhead` 提前解**可见区间之后 6 格**，只 enqueue 不组合节点，
  结果直接进 memoryCache，滑到时 0 延迟。**必须本地去重**（rangeTo 每帧变）。
- 尺寸要和 `DayCell` 的主请求**完全一致**（`wPx * THUMB_DECODE_SCALE`），
  否则 memoryCacheKey 对不上，白解。改解码倍数时这里要跟着改。
- 内存缓存 25% → 30%。
