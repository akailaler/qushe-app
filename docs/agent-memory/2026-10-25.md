  5xx / TimedOut / UnexpectedEof，**403/404 立即放弃**

  时 `bytes_stream()` 不可用），整体包 180s `tokio::time::timeout`，

- `#[tracing::instrument]` 在 impl 内部，把它当锚点插函数会插进 impl 里，

  **极难发现**。真正的 cargo 在
  `C:\Users\<用户名>\.rustup\toolchains\stable-x86_64-pc-windows-msvc\bin\cargo.exe`。
- **构建必须在英文路径 `C:\wb-build`**（中文路径 `小工具\...` 下写 `target/`
  会被安全策略拒）。源码用 `cp -Rf src/. dst/` 同步过去即可，
  **不要用 `sync.bat`**（bash 调它时中文路径编码会被打乱）；
  **也不要在 bash 里用 `robocopy /MIR`**（MSYS 把 `/MIR` 当路径转，
  必须 `export MSYS_NO_PATHCONV=1`）。
- 构建命令：`cd C:\wb-build\tauri-app && npx vite build` 然后
  `npx tauri build --bundles nsis --config tauri.override.json`
  （需 vcvars 的 LIB/INCLUDE + PortableGit 在 PATH）。产物在
  `C:\wb-build\target\release\bundle\nsis\`。
- **`sed -i` 在这个目录会失败**（`cannot rename ./sedXXXX: Permission denied`），
  改用 Edit 工具；**失败会留下 `sedTbi7Q3` 临时文件，`git add -A` 会把它提交进去**。

### 构建进程"挂住不报错"也是沙箱拦截的一种表现

重启构建后**不再报 `拒绝访问`，而是 rustc 挂住**：`time` / `sqlx_core` 两个 rustc
进程 CPU 时间几乎不涨、`rt/release/deps` 半小时没有新文件。**判断方法：**
`Get-Process rustc` 看 CPU 秒数 + `find <target> -newermt "-2 minutes"` 数新文件，
两个都不动就是卡住，不是"大 crate 编得慢"。
⇒ 后台跑构建**一定要带沙箱豁免**；不带的表现为挂起而非失败，白等 25 分钟。

### 第二轮：关窗弹崩溃报告的根因（★ 最重要的教训）

用户报"点关闭就弹崩溃报告然后重启"。追下去发现**是我第一轮改出来的**。

**根因**：程序退出时要**回写广告统计**（`[MTKK_Stat]` 的 `AD_BFPane` 等）。
把 `imgTmp\config\` 整目录改名后，那条回写回调拿不到结构 ⇒
`EXCEPTION_ACCESS_VIOLATION` / `STATUS_FATAL_USER_CALLBACK_EXCEPTION (0xc000041d)`，
于是每次关窗都崩、都弹 CrashReport.exe。

**四种"删除式"改法全炸**：
| 改法 | 结果 |
|---|---|
| 整目录改名 | 启动正常，**关窗崩** |
| `<BPaneBtn>` 删子节点 | 启动即崩 0xc0000005 |
| 整段删 `<BF>/<SF>` | 同样崩 |
| `Channel` 改不匹配值 | 广告消失，**关窗仍崩** |

**唯一安全解**：结构原样保留，只把 `1.jpg` 换成侧栏背景色纯色图（#4C4C4C, 208×110）。
控件照建、统计照写，视觉上消失。**改完关窗不再崩。**

**★ 排查方法论**（这次全靠它定位）：
① 用干净副本做对照（`robocopy` 到 D 盘跑），隔离"程序文件"变量；
② 用**系统事件日志**判定崩溃，别靠肉眼看窗口 ——
   `Get-WinEvent Application/Application Error` 看 `KanKan.exe` 的异常码与偏移；
③ 同一份日志里两种偏移（002a49a0 / 00082ad4）对应两种不同的坏改法。
