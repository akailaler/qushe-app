## 环境坑
- **`javac -version` 输出到 stdout**（`java -version` 才走 stderr）。setup.py 一开始只读 stderr，
  导致明明装了 JDK 却报"找不到"。两个都读。

## 1.3.76（安装包 32.6MB → 3.7MB）

### ★ 瘦身先看构成，别凭直觉动
debug 包 32.6MB 的构成实测：**dex 32MB（99%）**、资源 761KB、native 库 44KB。
⇒ "删 x86/armeabi 库""压资源"**全是无效功**（最多省几十 KB），唯一有效的是**代码裁剪 R8**。
开 `isMinifyEnabled + isShrinkResources` + `signingConfig = debug` ⇒ **3.7MB（-89%）**。
- release 用 debug 签名 ⇒ 能直接 `adb install`，也能覆盖安装现有 debug 包。
- **release 不可 `run-as`**（`not debuggable`）⇒ verify.py 的收藏核对要用 debug 包。
  verify.py 已区分这两种情况（`adb()` 加了 `with_stderr`，否则报错全被丢掉）。
- 混淆后的崩溃堆栈要看 `app/build/outputs/mapping/release/mapping.txt`（39MB，**不进仓库**）。

## 两台机器的方案（用户问）
- **两边都装 WorkBuddy 会更简单**，但简化的是**操作**不是**机制**：
  WorkBuddy 不会把 `.workbuddy/memory/` 在两台机器间同步，它只是本地文件。
  机制仍然是 git + `docs/agent-memory/` 镜像 + `setup.py`。
- 更简单的点是：**用户说一句"我换机器了"，我就能 clone + setup + 恢复记忆**，不用他敲命令。
- **不推荐把工作区放网盘同步目录**（`.git` 会被锁定/冲突难解）。
