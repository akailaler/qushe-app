## 1.3.65（已构建 + 已装机 + 已入库）

### ★ 同一个参数往往同时管着好几件事，去掉它会连带别的
`contentRatio` 看着只是"图片比例"，实际管着两处：
① `snapScale`（吸边界/放大上限）② `decodeSize`（给 Coil 的解码尺寸）。
1.3.62 为了解决"长图被锁死在 1x"把 `contentRatio` 整个去掉 ——
上限是放开了，但**解码尺寸也跟着退化成容器尺寸** ⇒ 长图放大后必然是插值的糊图。
**正解：拆开。加 `sourceSize`（原始像素）专门给 decodeSize 封顶。**
教训：改一个"看起来只管一件事"的参数前，先 grep 它到底被谁读了。

### overlayContent 要做成 BoxScope
`MediaPreviewOverlay` 的 `overlayContent` 原本是 `() -> Unit`，
调用方拿不到 `align`，只能自己套一层 `Box`（我就是这么改坏的）。
**直接把类型改成 `BoxScope.() -> Unit`**，调用方就有 BoxScope 了。

### Dialog 窗口层级这条已经踩了两次
日期视图、详情面板都必须走 `overlayContent`（同一个 Dialog 窗口），
用 ModalBottomSheet 会被压住。第一次踩的时候找了三个错方向才找到根因。

## 1.3.66（已构建 + 已装机 + 已入库）

### "信息胶囊 vs 详情面板"的分工规则（用户定的，全 App 统一）
- **胶囊只有一行**：只放 `日期 · 文件夹 · 大小`。
  分辨率/时长/地点/EXIF 一律进详情面板 —— 塞进胶囊的结果是挤成一团再被省略号截断。
- 三个页面共用同一个 `InfoPill` + 同一个 `PhotoDetailContent`；
  **胶囊出现多次就要有唯一构造函数**，各写各的必然漂移。
- 信息入口的**位置**要和操作按钮区分：胶囊居中（它是信息），按钮靠边（它是动作）。

### "拍摄时间"和"添加时间"是两回事
截图 / 下载 / 微信保存的文件，拍摄时间（EXIF）与入库时间（`DATE_ADDED`）可能差好几年，
混成一个"日期"会让人以为图是那会儿拍的。`MediaItem` 加 `dateAddedMillis`（单位是**秒**，进模型统一成毫秒）。
两者相同时只显示一行。

### 危险操作后的 IO 要"先出内容、后填数据"
详情面板点开即显示，地名/EXIF 用 `LaunchedEffect` 后台读 —— 不让用户等 IO。

### ★★★★ LaunchedEffect 在内部改自己的键 ⇒ 协程自取消
`LaunchedEffect(pendingAddBatch) { pendingAddBatch = emptyList(); addSyncer.launch(...) }`

### 踩坑（都很费时间，值得记）
- **cmd 批处理用 GBK 解析**：`.bat` 里的中文注释和中文路径会被打乱并当成命令执行。
  **构建脚本必须纯 ASCII，且在含中文的路径下 `cargo build` 必须搬到英文目录**（用了 `C:/wb-build/`）。
- **winget 装 Rust 会留下 0 字节的 shim**（`~/.cargo/bin/*.exe` 全是 0 字节），
  报"不是此操作系统平台的有效应用程序"。
  解法：`rustup toolchain uninstall stable` 后重装；期间直接用
  `~/.rustup/toolchains/stable-.../bin/cargo.exe` 真实二进制（shim 坏时仍可用）。
- **VS Build Tools 必须装**（Rust 在 Windows 链接需要 MSVC）：
  `winget install Microsoft.VisualStudio.2022.BuildTools --override "--quiet --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"`，
  构建前 `call vcvars64.bat` 载入 INCLUDE/LIB。
- **cargo 的 git 依赖**（weibosdk-rs 来自 GitHub）在 cmd 环境里找不到 git →
  把 PortableGit 的 `cmd` 和 `usr\bin` 加进 PATH，并配
  `git config --global url."https://ghfast.top/https://github.com/".insteadOf "https://github.com/"`。
- crates.io 走 rsproxy 镜像（`~/.cargo/config.toml` 的 sparse 源）。
- npm 依赖用 `YARN_NPM_REGISTRY_SERVER=https://registry.npmmirror.com`（项目是 yarn 4，
  由 corepack 提供；`corepack enable` 才能用 yarn）。
- **MUI v9 已移除 `inputProps`**，Checkbox 的 aria-label 要写 `slotProps={{ input: {...} }}`。
- **写 React 回调时注意 setState 异步**：`onInject` 里 `setUserInput(u)` 之后，
  同一回调里读 `userInput` 拿到的还是**旧值** —— 必须让回调直接传出 `u`。
- sea-query：join 条件用 `.eq(...)`（不是 `.equals`）；计数对齐现有风格 `Func::count(1).into()`。

## WeiBack-rs 定制版 0.3.3：修两个"没验证就交付"的 bug（10/17）

用户反馈：批量删除从不成功、作者列表没法用。**根因全在日志里，我上一轮没看日志就交付了。**

### bug 1：`ambiguous column name: id`
sea-query 的 `group_by_col(UserIden::Id)` 生成的 SQL 是 `GROUP BY id`，**不带表前缀**。
users 和 posts 都有 id 列 → SQLite 报错。
**我上一轮的"验证"是用 Python 手写 SQL（带了 `u.id` 前缀）跑通的，完全没验证
sea-query 实际生成的 SQL。** 教训：**用查询构造器时，必须验证它生成的 SQL 文本**，
不能拿自己手写的等价 SQL 代替。
修法：改成手写 SQL（`GROUP BY u.id, u.screen_name`）。

### bug 2：批量删除从不成功，日志里连调用记录都没有
前端 `deletePosts(ids: string[])` → Rust 签名 `ids: Vec<i64>`。
微博 ID 是 19 位大数，**JS 只能用字符串传**（否则丢精度），
而 `Vec<i64>` 反序列化字符串数组直接失败。
官方 `DeletePostOptions` 正是为此用 `#[serde_as(as = "DisplayFromStr")]`，我漏了。
修法：仿照官方加 `DeletePostsOptions { #[serde_as(as="Vec<DisplayFromStr>")] ids, deep }`。

### bug 3（安装层面，最隐蔽）：装完了还是旧代码
定制版和官方版**版本号都是 0.3.2-beta**，NSIS 发现版本相同就**跳过文件覆盖**，
静默安装返回 0，但 exe 没被替换。
**排查方法：比对安装后 exe 的 LastWriteTime**，一眼看出没更新。
修法：版本号提到 0.3.3。

### 踩的编译坑
- `#[serde_as]` **只能用于 struct/enum，不能用于函数**（E0438? 报的是
  "attribute can only be applied to struct or enum definitions"）。
- 删 `use sea_query::{...}` 时把同文件其他函数仍在用的 `AssertSqlSafe` 一起删了 →
  E0425。**清理导入要逐个确认还有没有别的引用。**

### 正确的验证姿势（本次做到位了）
1. 装完先比对 exe 时间戳，确认真的覆盖了
2. 启动后 `grep -E "命令名|ERROR" weiback.log`
   —— 用户连点 5 个作者，日志出现 5 条不同 `user_id` 的 `query_local_posts`，
   零 ERROR，这才是功能真在跑的证据。

## WeiBack-rs 定制版 1.0.0：UI/交互/性能六项（10/22）

源码已建 **git 仓库**（`weiback-rs-src/.git`，main 分支，基线提交 168 文件 / 65511 行），
版本号改为 **1.0.0 起独立递增**（Cargo.toml workspace + tauri.conf.json + package.json 三处都要改）。

本轮用户反馈与修复：
1. **批量删除确认框跑到左上角还铺满全屏** —— `<Modal>` 里的 Box 没定位样式。
   修：Modal 加 `sx={{display:'flex',alignItems:'center',justifyContent:'center'}}`，
   Box 给 `width:'90vw'/'480px'` + `maxHeight:'90vh'`。

   把 webview 主线程卡死。**症状是"白屏/无响应"，根因是查询+渲染双慢。**

4. **本地作者页没有图片放大** —— 我之前传的是 `onImageClick={() => undefined}`（没实现）。
   补上 Modal + FullSizeImage。

### 两个值得记住的坑
- **SQLite WAL 模式下，`shutil.copy2` 只复制 `.db` 会丢最新提交**：
  我因此误判"索引没创建"（实际迁移已成功、索引已在）。
  要验证真实库状态就直接**只读连接原文件**（`file:...?mode=ro`），不要复制。

  看 `weiback.log` 里的 `slow statement` 警告能直接定位。
