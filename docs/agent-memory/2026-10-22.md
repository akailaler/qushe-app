# 2026-10-22

## 1.3.88（设置页「检查更新」+ 收藏同步的机型边界）

### ① 用户的第二台设备：红米 K20 Pro / MIUI 12.5.6（Android 11）

反馈三件事：收藏同步双向都无效、加载图片有时慢、想要手动检查更新。

**收藏同步的结论：这台设备的相册不写 MediaStore 的 `is_favorite`。**
- 反向（系统 → 应用）：`allSystemFavoriteKeys()` 读到 0 条 —— 相册里的收藏
  存在小米相册自己的库里，没有落到 MediaStore。
- 正向（应用 → 系统）：`createFavoriteRequest` 不报错、读回校验也能过
  （所以 UI 显示"已同步"），但相册 App 不读这一列 ⇒ 用户看不到。
- 这不是我们的 bug：同一个功能在 HyperOS 3.0 那台机器上 286 条逐条对齐。
- **验证方法**（给用户）：在相册里手动收藏一张 → 取舍里点「同步系统收藏到这里」→
  若提示"没有读到任何收藏"，就证实是相册不写这个标记。
- 代码层面能做的都做了（写后读回校验 + 如实提示），**没有可绕过的正规路径**。

### ② 新功能：检查更新

- `core/UpdateCheck.kt`：查 `api.github.com/repos/akailaler/qushe-app/releases/latest`，
  取 `tag_name` 与本地 `versionName` 按点分段比较（不能按字符串比，`1.3.9 > 1.3.10` 会错）。
- 设置页底部（"管理权限"之后）加一行：**检查中… / 已是最新 / 发现新版本 → 去下载**。
  点"去下载"直接开浏览器到 release 页。
- 清单加 `INTERNET` 权限，**只有这一个请求会联网**，不做后台轮询、不上报。
- 失败一律降级成文案（超时 / 403 限流 / 404 没有 release），不抛异常。

### ③ 加载慢：暂不改

K20 Pro 是骁龙 855 + UFS 2.1，慢的是**随机读 + 解码吞吐**，不是逻辑问题。
已经做了的：0.75 倍解码、系统缩略图垫底、长图区域解码。
再快只能牺牲清晰度（降到 0.6）—— 用户对糊很敏感，先不动。需要问清是哪个场景慢。
